# 자료에서 역할별 수업 도구까지: 가계·기업 예시

이 예시는 완성된 연수자료와 분리된 **실제 로컬 서버 연결 프로젝트**다. 교사·가계·기업 브라우저가 같은 서버 기록을 읽고 바꾼다. 기존 `outputs/`나 운영 서비스를 수정하지 않는다. Node 22 이상과 기본 모듈만으로 실행하며, 설치·AI API·가입은 필요 없다.

```sh
node scripts/preview-economy.mjs --dest ../economy-example --serve --port 8798
```

새 폴더만 만들며 기존 폴더를 덮어쓰지 않는다. 출력되는 **교사 전용 주소는 교사만** 연다. 주소의 키는 브라우저에 저장하고 주소창에서 제거한다. 학생은 `/student/`로 입장한다. 같은 브라우저의 탭끼리는 같은 학생으로 복원되므로 역할을 나눠 체험하려면 별도 브라우저/프로필을 쓴다. 재실행은 생성 폴더에서 `npm start`로 한다. 서버를 종료할 때는 Ctrl+C.

이 구현은 단일 Node 프로세스의 JSON 저장소와 1초 간격 순차 조회를 사용하는 로컬 참조 예시이며 127.0.0.1에 바인딩한다. 서버를 여러 개 운영하려면 공유 데이터베이스의 트랜잭션으로 바꿔야 한다. 여러 독립 브라우저의 실제 HTTP 통신을 검증하지만 **학교 태블릿 접속·공개 배포를 완료한 것이 아니다**. 공개 운영으로 옮길 때 HTTPS·교사 인증/복구·세션 분리·저장소·보존/삭제·접속 제한과 공개 다중 기기 검증을 추가한다. 정적 파일 Drop으로 서버까지 배포됐다고 하지 않는다. 교사 키·학생 토큰·`.economy-data/`는 공개 폴더/커밋/소스 패키지에 포함하지 않는다.

## 먼저 읽고 나누기

예시를 만든 근거는 기존 연수의 PPT **저장된 추출문**과 사용자가 제공한 수업 대본이다. 현재 Downloads의 원본 PPT 파일을 다시 읽은 것으로 주장하지 않는다. 원문·표지·교과서 이미지는 재배포하지 않는다.

| 근거 | 확인된 내용 | 이 예시에서의 적용 |
|---|---|---|
| 기존 PPT 추출문 17~18쪽 | 소득 사용·직업 선택·기업 활동과 경쟁 | 가계가 일할 기업과 소비 대상을 선택, 기업이 상품/가격 선택 |
| 같은 추출문 21~23쪽 | 상품 개발·원가·판매 가격·주문·이윤을 살피는 치킨 활동 | 가격/재고/판매를 화면에 연결. 원본 치킨 경쟁 활동을 그대로 재현한 것은 아님 |
| 사용자 대본 | 태블릿 입장·자동 역할·교사 단계 제어·낮 노동/생산·밤 소비 | 준비 → 낮 → 밤 → 돌아보기, 역할별 화면과 서버 상태 |
| 예시 제작 가정 | 금액·상품·임금·재료·생산량은 원문에서 확정되지 않음 | 가계 40, 기업 120, 임금 20, 재료비 10, 생산 2개, 가격 10~50 |

원문 위치 기록: 기존 프로젝트의 `outputs/worker/lesson-material.js`와 `outputs/lesson-desktop.js`를 읽기만 했다. 추출문 파일 SHA-256 `bcc19f5964164e87bb16da19e15a485f3f3b966aca3c4bc574a464e09556ea51`. 실제 제작에서는 해당 사용자의 원본으로 대응표를 다시 쓴다. 예시의 숫자·상품·활동을 모든 연수에 강요하지 않는다.

## 만드는 흐름

1. **학습 의도를 행동으로 쓴다.** ‘가계와 기업 설명’에서 끝내지 않고 ‘가계가 일하면 기업이 임금을 지급하고 상품이 생긴다. 구매하면 돈과 재고가 반대로 움직인다’처럼 조작과 변화를 정한다.
2. **역할별 화면과 권한을 정한다.** 교사는 단계·멈춤·초기화·전체 현황, 가계는 내 예산·노동·소비·선택 이유, 기업은 상품/가격·생산 자금·재고·판매 현황을 본다. 다른 가계의 잔액/선택 이유는 학생 응답에 내리지 않는다.
3. **상태의 주인을 정한다.** 역할·단계·잔액·재고·거래·완료 여부는 서버가 소유한다. 브라우저는 다른 참여자의 상태를 임의로 쓰거나 가격/잔액을 확정하지 못한다.
4. **한 흐름을 먼저 끝낸다.** 입장 → 교사 낮 시작 → 기업 가격 → 가계 노동 → 교사 밤 시작 → 구매 → 선택 이유 → 교사 돌아보기를 실제 서로 다른 브라우저로 실행한다. 미리 채운 결과표로 대신하지 않는다.
5. **일관성과 복구를 붙인다.** 요청 ID로 중복 전달을 한 번만 처리하고, 잔액·재고·상대 계정·거래 내역을 한 저장 단위로 바꾼다. 저장 실패 시 아무 변화도 확정하지 않는다. 접속이 끊기면 마지막 화면/초안을 보존하며, 전달 결과가 불명확한 요청은 같은 ID로 재확인한다.
6. **검증 증거와 경계를 전달한다.** 아래 숫자·보이는 결과를 검사한다. 로컬 검증, 학교 기기 검증, 공개 운영 검증을 구분한다. 재사용할 때 UI 모양보다 계약과 학습 의도를 가져간다.

이 흐름은 신규 연수 전체 구성안 확인을 대신하지 않는다. 사용자가 이미 요청한 별도 기능 예시나 작은 수정에는 전체 연수 승인 절차를 다시 강요하지 않는다.

## 동작 계약

- 입장 순서대로 가계/기업을 번갈아 배정하고 서버에 고정한다. 실명 입력·경쟁 순위·승자는 없다. 선택 이유를 교사가 함께 해석한다.
- 낮에는 가계가 한 번 일할 수 있다. 기업 30 차감 → 가계 임금 20 증가 + 재료 비용 풀 10 증가 + 해당 기업 재고 2 증가. 자금이 부족하면 전부 거절한다.
- 기업은 낮에 상품과 가격을 정한다. 생산 후 상품 종류는 바꿀 수 없다. 밤에는 가격 변경을 거절한다.
- 밤에 가계가 고르면 서버의 현재 가격만 사용한다. 가계 잔액 차감·기업 판매 대금/잔액 증가·재고 1 차감·거래 기록을 함께 저장한다. 잔액/재고 부족, 단계 위반, 멈춤, 이미 마친 선택은 거절한다.
- 가계는 아무것도 사지 않고 이유를 남겨 마칠 수도 있다. ‘돈을 가장 많이 남긴 사람이 합리적’으로 채점하지 않는다. 도시락/스티커의 필요·선호는 체험 설정이며 실제 학생의 사정으로 일반화하지 않는다.
- 기업의 **운영 결과**는 판매 대금 − 지급 임금 − 재료비다. 미판매 재고 가치는 반영하지 않는 단순 현금 지출 기준이며, 원본 PPT의 판매 수량별 이윤 식과 동일하다고 설명하지 않는다.
- 밤에 늦게 입장한 가계는 기본 예산 40으로 소비하며 그날 임금을 소급 지급하지 않는다. 밤에 들어온 기업은 거래를 관찰하고 초기화 후 다음 체험에 참여한다. 이 규칙은 화면에도 표시한다. 돌아보기 단계에는 새 입장을 받지 않는다.
- 교사만 단계를 순서대로 넘기고 멈추거나 초기화한다. 초기화 취소는 보존, 확인은 새 수업 epoch로 역할·돈·선택을 지우고 이전 학생 토큰을 무효화한다. 진행자 접근은 유지한다.

## 검증 기준과 하네스

```sh
WORKSHOP_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs \
  node --test --test-concurrency=1 scripts/economy-lab.test.mjs
```

브라우저 도구가 없으면 [설치 선택 절차](setup-and-deploy.md)를 따른다. 테스트를 건너뛰었으면 다중 기기 동작을 검증했다고 하지 않는다. 이 저장소의 기존 Playwright를 사용하며 새 패키지 설치가 기본값은 아니다.

| 검사 | 관찰할 결과 |
|---|---|
| 독립 교사·가계·기업 브라우저 | 임금 20, 생산 2개, 구매 후 예산·재고·판매 대금이 모두 일치 |
| 권한과 노출 | 학생은 교사 제어/기업 가격을 대신 변경할 수 없고 다른 가계 기록/토큰/키를 받지 않음 |
| 요청 중복·응답 유실 | 같은 요청 ID를 다시 전달해도 노동·차감·판매·거래는 한 번 |
| 동시 구매·예산 부족 | 마지막 재고를 한 번만 판매, 음수 잔액/재고 없음 |
| 화폐 보존 | 모든 가계/기업 잔액 합 + 재료 비용 풀 = 각자의 초기 자금 합 |
| 저장 실패·재시작 | 쓰기 실패 시 모든 계정/거래 보존, 재시작 후 역할·잔액·거래 복원 |
| 끊김·재접속·늦은 입장 | 마지막 화면·선택 이유 보존, 복구 후 현재 교사 단계 반영 |
| 초기화 | 확인 전 보존, 확인 후 이전 학생의 접근 무효, 교사 접근 유지 |
| 휴대폰·태블릿·가로 화면 | 폼·가격·예산·구매/진행 버튼의 가독성·화면 내 위치, 키보드 조작 |

캡처는 교사 시장 화면·가계 구매 화면·기업 판매 화면과 작은 화면을 남긴다. 스크린샷만으로 원자적 거래·권한·복구 검사를 대신하지 않는다. `model.mjs`는 작동 규칙, `server.mjs`는 실제 저장/권한, `public/`은 역할별 화면이다. 상태 JSON은 비공개이며 각 변경은 검증된 복사본을 디스크에 저장한 뒤 확정한다.
