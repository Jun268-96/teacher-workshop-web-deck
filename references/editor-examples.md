# 현재 페이지로 보는 수정 예시

`/?edit=1`의 `수정 예시`는 **현재 페이지 읽기 → 어울리는 시안 세 가지 → 내 자료로 전후 조작 → 대상별 수정 요청 → 변경안 확인**으로 이어진다. 기본 작업은 연수 페이지와 내부 장면이며, 예시를 고른 일을 별도의 수업 앱 개발 요청으로 해석하지 않는다.

## 현재 페이지 추천

`editor-page-examples.js`는 정본의 요소와 현재 화면에 보이는 내용을 연결해 읽는다. 글·사진뿐 아니라 기존 화면 묶음/장면 내부의 문단·버튼·이미지도 소유 요소 ID와 자식 위치로 추적한다. 숨긴 탭·삭제 요소·빈 영역은 추천의 근거로 쓰지 않는다. 발표자 이름·기관명·로고는 페이지 추천의 내용 자료에서 제외하되 사용자가 해당 요소를 직접 선택한 경우에는 미리볼 수 있다.

추천은 **문구·단위·구조를 확인하는 로컬 규칙**이다. API 키 없이 즉시 동작하며, GPT가 전체 자료의 교육 맥락을 읽고 판단한 결과라고 표시하지 않는다. GPT가 실제 수정할 때는 요청과 전체 자료·앞뒤 흐름을 읽고 최종 장면과 동작을 설계한다.

| 자료에서 확인한 근거 | 추천/미리보기 |
|---|---|
| 글·사진 여러 개 | 원래 배치에서 클릭할 때마다 한 묶음씩 공개 |
| 실제 문장 | 문구를 고치지 않고 한 번에 하나씩 크게 표시 |
| 글·사진의 실제 위치 | 설명하는 부분에 집중 표시를 옮기거나 끄기 |
| 숫자와 명시적인 단위 | 해당 값까지 수치 재생. ‘약/이상/미만’, 단위·문맥 보존 |
| 현재 보이는 사진 둘 이상 | 내 사진으로 이전·다음 사진 보기 |
| 사진 설명에 수정 전·후가 명시된 한 쌍 | 내 사진의 비교 경계 이동 |
| 실제 질문 문구 | 내 질문에 답을 적고 모아보는 로컬 시안 |
| 번호가 붙은 작업 단계 | 실제 순서와 문구로 이전·다음 단계 보기 |

연도·학년·페이지 번호를 모션의 목표값으로 해석하지 않는다. 기존 시간 표기는 원문 그대로 미리볼 수 있지만, 이번 연수의 확정 시간·평균·비율·타이머 설정으로 가져오지 않는다. 서로 다른 사진을 임의로 전후 사례라고 부르지 않는다. 없는 질문·선택지·예산·상품·결과를 만들어 넣지 않는다. 읽을 수 있는 글·사진이 없는 선택 영역은 추천을 꾸며내지 않고 다른 대상을 고르도록 안내한다.

내용을 보존한 공개·큰 문장·집중 표시를 기본 대안으로 두어 보통 세 가지를 제안한다. 단순한 요소 하나에서도 의미 없는 숫자나 다른 사례를 끼워 맞추지 않는다. 각 추천의 이유와 실제로 사용할 내용을 함께 보여준다.

## 내 자료의 비포앤애프터

- 현재 페이지의 DOM과 계산된 스타일을 복제해 원본 쪽에 표시한다. 수정 시안에는 같은 문구·수치·사진을 사용한다. 원래 페이지의 요소·배치·행동·편집 버전은 바꾸지 않는다.
- 복제는 격리된 미리보기에서 수행한다. 스크립트·이벤트·링크 동작·외부 프레임을 실행하지 않는다. 영상과 입력/외부 영역은 정지된 표시로 대체하며 실제 AI/파일 처리/참여 서버를 호출하지 않는다. 미리보기는 수정 방향을 이해하는 시안이며 최종 코드의 모든 장식·재생 결과를 보증하지 않는다.
- 질문 체험은 미리보기 안에서 작성한 답만 보여준다. 실제 참가자 수·실시간 집계·제출 성공으로 표시하지 않는다. 사진과 글에는 내 자료를 사용하고 기본 ‘80%/공책/수업 자료.pptx’를 섞지 않는다.
- 선택 요소만 요청하면 그 요소의 자료를 다시 읽어 추천과 미리보기를 바꾼다. 작성 중 프롬프트는 예시/범위별로 보존하며, 원래 자유 입력 요청 초안은 건드리지 않는다.
- 닫기·페이지 이동·미리보기 종류 변경은 애니메이션/크기 관찰자를 정리한다. 키보드·터치·동작 줄이기를 지원한다. 휴대폰에서는 원본과 시안을 위아래로 비교하고 요청 버튼까지 내부 스크롤한다.

## 요청과 검토

`내 페이지에 수정 요청`은 실제 문서를 바로 바꾸지 않고 기존 요청 목록에 담는다. 목록에서 로컬 요청함에 저장하거나 지원되는 ChatGPT 주석으로 전달한다. API 호출·에이전트 자동 실행·전송 완료를 추정하지 않는다. [로컬 요청함](local-editor-inbox.md)의 변경안 확인·취소·확정·실행 취소로 이어간다.

요청에는 기존 page/object ID·편집 버전과 함께 다음 문맥을 담는다.

```text
context.scope: page 또는 object
context.example.demo: current-page-preview
context.example.reason: 현재 자료에서 확인한 추천 이유
context.example.proposal:
  kind, scope, sourceIds
  targets: 소유 요소 ID, 자식 위치, 타입, 내용 지문, 짧은 원문
  number: 수치 시안에만 원래 값/단위/문맥
```

원본 복제 HTML·계산된 CSS·내장 이미지/영상 바이너리는 요청에 넣지 않는다. 요청함의 비공개 정본과 원본 프로젝트가 실제 수정 재료다. 다른 페이지/버전으로 바뀌었거나 같은 버전에서 동적 영역의 내용이 달라지면 요청을 거절하고 다시 확인하게 한다. 자식 위치는 요소 선택의 근거이며 임의 JavaScript나 셸 명령으로 실행하지 않는다.

## 기존 기능 예시

`기능 예시`에는 기존 여덟 가지 공통 체험(공개·모션·비교·사진 슬라이드·추첨·참여 모형·선택 상황·파일 작업 대본)을 유지한다. 이 화면은 **동봉 체험용 자료**라고 구분한다. 세 가지 추천과 내 자료 미리보기는 기본 탭에서 제공한다. 기존 `장면` 삽입·직접 편집·동작 연결·영상·가져오기·내보내기·참여 서버 기능은 그대로 유지한다.

별도의 가계·기업 앱은 이 흐름의 기본 출력이 아니다. 사용자가 독립 앱을 요청할 때만 참고한다.

## 검증

`page-examples.test.mjs`는 실제 글/수치/사진/질문과 묶음 내부 요소 읽기, 세 가지의 적합성, 단위·범위 보존, 조작 후 원본/초안 보존, 범위 재선택, 요청함/주석 문맥, 변경된 버전/동적 내용 거절, 단일 사진·빈 영역, 반응형, 발표 HTML에서 편집 예시 제거를 검사한다. 기존 `editor-examples.test.mjs`의 여덟 공통 체험과 전체 편집·참여 회귀 검사도 실행한다. 캡처에서 원문 가독성·사진·추천 이유·버튼 위치를 직접 확인한다.
