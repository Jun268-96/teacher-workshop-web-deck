# 편집기의 수정 예시

처음 사용하는 교사는 CSS 효과 이름을 고르는 대신 **수정 전 → 직접 눌러보는 수정 후 → 짧은 요청**으로 바뀔 결과를 이해한다. `/?edit=1` 상단의 `수정 예시`에서 연다. 별도 튜토리얼을 강제로 띄우지 않는다.

## 동봉 체험과 실제 수정의 경계

| 예시 | 직접 해볼 조작 | 실제 요청에서 확인할 것 |
|---|---|---|
| 한 번에 하나씩 | 다음 보기로 설명을 공개 | 클릭 순서·다시 보기·바깥 페이지 이동 분리 |
| 숫자를 실감나게 | 숫자와 막대 재생 | 자료의 확정 숫자·단위, 동작 줄이기 |
| 차이가 보이는 비교 | 전후 경계 이동 | 실제 두 자료의 같은 부분·배율·출처 |
| 사진 한 장을 크게 | 이전·다음 사진 | 사진 순서·핵심 영역·짧은 설명 |
| 설명 대신 직접 실행 | 인원수를 입력하고 추첨 | 주제에 맞는 도구, 입력 오류·반복 실행 |
| 두 화면이 함께 변하기 | 참가자 제출 → 진행자 결과 | 체험은 로컬 모형. 실제 서버·권한·재접속·두 기기 검사 |
| 선택하면 상황이 변하기 | 물건 선택 → 예산 변화 → 다시 선택 | 예시 수치를 복사하지 않고 교과 목표·자료에 맞게 규칙 설계 |
| 작업 순서를 직접 시연 | 파일 드롭/클릭 → 첨부 → 다음 질문 | 대본 시연과 실제 파일 분석·AI 응답 구분 |

앞의 네 장면은 기존 `장면` 메뉴에서 즉시 삽입할 수도 있다. 뒤의 예시는 **체험과 수정 요청**이며 버튼만 누르면 실제 앱이 생성되거나 서버가 연결되는 것은 아니다. API 호출·비용·설치를 자동으로 추가하지 않는다. 동봉된 그림·수치·파일은 체험용이다. 사용자 파일이나 실제 참가자 응답으로 소개하지 않는다.

## 내 페이지로 연결

- 이미지 수·숫자·관련 단어를 이용한 로컬 규칙으로 예시 세 개를 앞에 보여준다. GPT가 원문을 읽고 내린 추천이라고 주장하지 않는다. 전체 예시는 항상 접근 가능하다.
- 예시를 열 때 현재 페이지 ID·선택 요소 ID·편집 버전을 고정한다. 기본 대상은 현재 페이지이며, 이미 선택한 요소가 있으면 그 요소만 대상으로 바꿀 수 있다. 페이지에 요소가 없으면 먼저 요소를 추가하게 안내한다.
- 프롬프트는 고쳐 쓸 수 있다. 창 안에서 다른 예시를 오가도 작성 중 문구를 유지한다. 기존 자유 입력 요청 초안은 건드리지 않는다.
- `내 페이지에 수정 요청`은 기존 요청 목록에 추가한다. 문서·배치·기능 자체는 바꾸지 않는다. 목록에서 프로젝트 요청함에 저장하거나 지원되는 ChatGPT 주석으로 한 번에 전달한다. 에이전트가 자동 실행됐다고 표시하지 않는다.
- 요청에는 `context.scope`, `context.example`(ID·제목·체험 구분·구현 시 확인할 의도), 페이지 요소 ID/종류/문구 요약, 기존 대상 문맥과 버전을 담는다. 이미지/영상의 내장 바이너리는 프롬프트나 문맥에 복제하지 않는다. 정본은 기존 비공개 요청함의 편집본에 포함한다.
- 페이지가 바뀌면 창을 닫고, 같은 페이지에서 편집 버전이 바뀌면 요청을 거절하고 다시 대상을 확인하게 한다. 과거 대상 요청을 새 페이지에 조용히 붙이지 않는다.
- 에이전트는 요청을 읽고 자료의 의미·관련 화면·발표 노트·작동 규칙을 확인한 뒤 구현한다. [로컬 요청함](local-editor-inbox.md)의 변경안 미리보기·확정·실행 취소로 이어간다.

## 검증

`editor-examples.test.mjs`는 여덟 체험의 조작·초기화, 예시만 보고 닫았을 때 문서/요청/기존 초안 보존, 대상별 요청/버전 거절, 요청함 저장, 주석 전달, 모바일·태블릿·가로 화면, 발표용 HTML에서 편집 예시 제거를 검사한다. 체험용 두 화면이 바뀌는 검사는 실제 다중 기기 서버 검증을 대신하지 않는다. 실제 공유 기능은 별도의 참여 서버 회귀 검사를 따른다.
