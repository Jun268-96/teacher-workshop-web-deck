# 실행 흐름

1. **현재 상태 확인**: 새 프로젝트/기존 자료 구분, 실제 서비스 경로·설정·사용자 작업 확인. 기존 자료를 템플릿으로 덮지 않는다.
2. **브리프**: `intake.md`로 빠진 조건만 수집. `workshop/brief.md`에 확인 사실과 가정 기록.
3. **자료 분류와 조사**: `source-inventory.md`에 필수 메시지/근거/대본/선택 내용/제외 자료 구분. 자료가 짧거나 부족하면 `research-and-formats.md`에 따라 공개 출처와 실제 사례를 조사하고 근거·확인일을 추가한다. 실제 사례는 `case-register.md`에 출처와 상태 기록.
4. **유형·시간·흐름 구성**: `narrative.md`, `slide-map.md`에 청중의 변화, 발표자/청중 행동, 대략 시간, 핵심·선택 구간, 증거·대체 장면 기록. 발표형/실습형/워크숍형에 맞춰 설명·시연·참가자 작업·확인/피드백·질문/휴식 시간을 배분하고 총합을 맞춘다. 실습의 결과물·완료 기준·도구 준비·막힘 대응도 정한다. 고정 장수/9장 구조나 15분 길이를 강요하지 않는다.
5. **한 번의 방향 정렬**: 아직 승인되지 않은 큰 구성·실시간 기능·배포 범위만 확인. 이미 정해진 방향과 일상적인 배치는 반복해서 승인받지 않는다.
6. **제작**: 새 프로젝트는 `starter-deck.md`로 생성. `public/`에 화면·에셋, `workshop/speaker-notes.md`에 대본·출처·운영 메모. 필수 장면 → 실제 자료 → 선택 모듈 순으로 구현.
7. **검증·보수**: `verification.md`. 정적 검사 후 실제 브라우저 조작·5종 화면 캡처. 대본 전체를 화면에 넣었는지, 필요한 차이가 보이는지 직접 판단한다. 실패를 고치고 영향 범위만 재검사한다.
8. **배포**: 범위에 포함됐으면 `setup-and-deploy.md`에 따라 도구·계정·대상 확인 후 진행. 정적 자료/실시간 서버를 구분한다. 공개 URL과 실제 빌드를 확인.
9. **전달**: 발표/참여 링크, 소스, 검사 결과, 생략한 검사와 당일 확인 사항만 간결하게 전달. 실제 자료가 없어 비워둔 장면은 완성 사례로 보고하지 않는다.
