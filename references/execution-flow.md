# 실행 흐름

1. **현재 상태 확인**: 새 프로젝트/기존 자료 구분, 실제 서비스 경로·설정·사용자 작업 확인. 기존 자료를 템플릿으로 덮지 않는다.
2. **입력 경로와 브리프**: 주제 기반/기존 자료 기반을 구분하고 `intake.md`로 빠진 조건만 수집. 기존 자료 변환은 `existing-materials.md`를 읽고 원본 흐름 유지/재구성 방향을 확인한다. 실습/참여 활동 여부와 필수 내용은 기존 답이 없으면 반드시 질문하고 응답·명시적 위임을 확인한다. `workshop/brief.md`에 확인 사실과 가정 기록.
3. **자료 분류와 조사**: `source-inventory.md`에 필수 메시지/근거/대본/선택 내용/제외 자료 구분. 자료가 짧거나 부족하면 `research-and-formats.md`에 따라 공개 출처와 실제 사례를 조사하고 근거·확인일을 추가한다. 실제 사례는 `case-register.md`에 출처와 상태 기록. 기존 자료는 원본 쪽/구간과 새 페이지·대본·승인 생략의 대응도 기록한다.
4. **장면 추천·체험·선택과 흐름 구성**: `scene-discovery.md`로 자료의 근거 위치와 기능을 연결해 추천한다. 동봉 일반 예시를 체험하고 고른 장면·명시적 제외 이유를 `scene-selections.md`에 기록한다. 이미 선택한 기능을 재질문하거나 모든 기능을 고르게 하지 않는다. `narrative.md`, `slide-map.md`에 청중의 변화, 발표자/청중 행동, 대략 시간, 핵심·선택 구간, 증거·대체 장면을 기록한다. 발표형/실습형/워크숍형에 맞춰 설명·시연·참가자 작업·확인/피드백·질문/휴식 시간을 배분하고 총합을 맞춘다. 실습의 결과물·완료 기준·도구 준비·막힘 대응도 정한다. 고정 장수/9장 구조나 15분 길이를 강요하지 않는다.
5. **전체 페이지 구성안 확인**: 모든 페이지의 제목·핵심 내용·선택한 기능을 쓰는 이유와 화면 상태·발표자/참가자 행동·예상 시간을 제시한다. 총 시간과 기능 범위·미확정 자료를 설명하고 사용자 승인을 기다린다. 예시 선택만으로 구성안이 승인됐다고 판단하지 않는다. 승인 전에는 조사·자료 정리·텍스트 구성안과 동봉 일반 예시 체험까지 진행한다. 승인 응답과 해당 구성 버전을 `slide-map.md`에 기록한다. 이미 승인된 안이나 작은 수정은 재승인받지 않는다. 구체적인 기준은 `decision-guides.md#page-plan-approval`을 따른다.
6. **제작**: 새 프로젝트는 `starter-deck.md`로 생성. `public/`에 화면·에셋, `workshop/speaker-notes.md`에 대본·출처·운영 메모. 필수 장면 → 실제 자료 → 선택 모듈 순으로 구현.
7. **검증·보수**: `verification.md`. 정적 검사 후 실제 브라우저 조작·5종 화면 캡처. 대본 전체를 화면에 넣었는지, 필요한 차이가 보이는지 직접 판단한다. 기존 자료 변환은 원본과 내용·수치·인용·실습의 누락/의미 변화도 대조하고 승인된 생략과 구분한다. 실패를 고치고 영향 범위만 재검사한다.
8. **배포**: 범위에 포함됐으면 `setup-and-deploy.md`에 따라 도구·계정·대상 확인 후 진행. 정적 자료/실시간 서버를 구분한다. 공개 URL과 실제 빌드를 확인.
9. **전달**: 발표/참여 링크, 소스, 검사 결과, 생략한 검사와 당일 확인 사항만 간결하게 전달. 실제 자료가 없어 비워둔 장면은 완성 사례로 보고하지 않는다.
