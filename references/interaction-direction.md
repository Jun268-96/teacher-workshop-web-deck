# 자료를 읽고 작동하는 연수 장면으로 만드는 기준

## 편집기의 역할, GPT의 역할

직접 편집기는 발표자의 문구·사진·영상·배치를 빠르게 고치는 수단이다. 제작의 중심은 **GPT가 자료의 의미와 발표 흐름을 읽고, 그 자리에서 조작할 수 있는 도구·변화·참여 흐름을 설계하고 구현하는 것**이다. 사용자에게 웹 기능을 상상해 이름 붙여 달라고 요구하지 않는다. 새 연수에서는 짧은 추천을 전체 구성안에 담아 확인하고, 승인 뒤에는 버튼 모양·클릭 단계·기본값·전환·복원 같은 구현 결정을 매번 되묻지 않는다. 이미 선택한 기능/위임 범위를 존중한다.

장면을 먼저 고르고 내용을 끼워 맞추지 않는다. **이번에 이해시킬 것 → 발표자가 할 행동 → 청중에게 달라지는 것**이 먼저다. 기능이 설명에 기여하지 않으면 정적인 큰 글자·사진으로 남긴다. 효과 수를 채우거나 페이지마다 움직이게 만들지 않는다. 시작 시에는 핵심 한 가지가 보이고, 세부는 그 순간에만 나온다.

## 기존 연수에서 확인한 재사용 패턴

아래는 이전 ‘AI로 만드는 에듀테크 및 학급 경영’ 웹 연수의 화면/소스에서 추출한 판단 기준이다. **15분, 연구회 로고/캐릭터, 작업 시간 수치, 개인 대화, API 키, 운영 기록은 기본값이 아니다.** 원본 프로젝트가 없어도 아래 계약만으로 새 자료에 맞춰 제작한다.

| 자료의 신호 / 전달 목적 | 실제 연수의 장면과 일반화 | 구현 경로 |
|---|---|---|
| 한 번에 끝날 것이라는 오해를 바꾸기 | `iteration`: 웹앱 등장 → 클릭 도장 → 다음 클릭에 수치/막대 증가. 새 주제에 맞는 오해와 근거 있는 수치를 사용 | 클릭 단계는 내장 reveal, 수치는 motion 또는 조합한 소스 장면. 자극적인 낙인/문구는 자동 복제하지 않음 |
| 무엇이 바뀌었는지 증거로 설명 | `idea/brief/design/revise`, `stack-story.js`: 같은 화면/영역을 잘라 전후 비교, 필요할 때 이전 요청과 전체 이력 열기 | 내장 compare/carousel, 필요 시 잘라 보여주기·집중 영역·버전 탐색을 코드로 확장 |
| 기능을 설명하는 대신 직접 사용 | `platform-local`, `platform-demos.js`: 추첨·타이머·자리/모둠·체크리스트를 내부 탭에서 실제 조작 | 새 자료의 예시 도구를 신뢰된 소스 코드로 구현. 그림이나 영상만 놓고 실제 도구라고 부르지 않음 |
| 서버가 필요한 이유를 경험 | `platform-shared`, `platform-live.js`: 제출·공지 읽음·설문·독서 기록·링크 공유가 발표자와 참여자에 반영 | 선택형 참여 참조 서버의 지원 범위부터 확인. 링크 공유/책 검색 등 추가 기능은 실제 서버·권한·실패 복구를 구현해야 함 |
| 청중의 상태에 맞춰 설명/실습 전환 | `ai-survey`, `participate/`, `workshop-flow.js`: QR로 참여, 응답 집계, 진행자 장면에 따라 참여 화면 전환, 자유 탐색/따라가기 | 설문/Q&A 등은 동봉 참여 모듈. QR·참여 화면 동기화·운영 흐름은 프로젝트 계약에 맞게 추가. 개인정보 공개 범위를 확인 |
| 작업 순서 자체를 시연 | `materials`, `lesson-desktop.js`: 파일 드롭 → 첨부 카드 → 다음 질문 입력 → 응답/대화 축적 | 실제 연동이 없으면 대본 재생임을 표시. 실제 AI는 서버 Secret·첨부 시점·이력·진행 중/오류/재시도 필요. 결제/API 호출을 자동으로 추가하지 않음 |
| 설명의 맥락을 화면 안에서 확인 | `use`의 항목별 화면 미리보기, 용어의 짧은 설명, 숫자 목차·확대 QR | 선택한 요소의 tooltip/사진 교체/보이기 동작 또는 소스 확장. 터치·키보드로도 열고 닫을 수 있게 함 |
| 핵심을 쉬게 하거나 단원을 전환 | `platform-intro`, `lesson-intro`, `start-small`, `closing`: 한 문장/단원 제목을 크게 | 정적인 텍스트 장면도 적극 선택. 캐릭터·장식·모션은 별도 요청이 있을 때만 |

**지원 수준을 구분한다.** 기본 편집기의 바로 삽입 장면은 reveal/compare/motion/carousel 네 가지다. 장면 실험실의 나머지 효과는 체험/참고용이며 모두 편집기 버튼으로 구현됐다고 주장하지 않는다. GPT는 승인된 내용에 맞는 도구/조합 장면을 HTML·CSS·JS 소스로 추가할 수 있다. 실시간 서버나 AI 기능은 자동으로 존재하지 않는다. `live-modules.md`, `participation-runtime.md`의 계약과 검사를 따른다.

## 자료를 받은 GPT의 진행

1. 원본의 주장·숫자·순서·화면·관찰/활동·실습을 읽는다. 빠진 교육 맥락은 `intake.md`에 따라 짧게 확인하고 필요한 근거를 조사한다.
2. 전달 효과가 큰 위치를 골라 **자료 근거 + 구체적인 청중 경험**으로 추천한다. 예: ‘이 페이지는 참가자가 선택한 대응에 따라 교실 상황의 결과가 달라지게 하고, 이어서 선택 이유를 비교하겠습니다.’ CSS 용어·긴 기능 메뉴로 되묻지 않는다. 기존 단순 수정에는 새 기획 절차를 강요하지 않는다.
3. 구성안에는 초기 화면, 조작 후 화면, 발표자/청중 행동, 필요한 자료/서버, 실제/예시 구분을 함께 적는다. 사용자가 승인한 뒤 구현하고, 사소한 연출은 목적과 시각 톤에 맞게 스스로 정한다.
4. 제작 중 `workshop/interaction-plan.md`에 아래 계약을 짧게 남긴다. 프로젝트에 동등한 계획이 있으면 중복 문서를 만들지 않는다. 다른 GPT/Claude나 다음 수정 요청도 이어받을 수 있는 내용만 기록한다.

```text
페이지 ID / 원본 위치·핵심 메시지
왜 정적 화면보다 도움이 되는지 (도움이 없으면 정적 유지)
처음 보이는 것 → 클릭/입력/제출 → 바뀌는 것
데이터의 출처 / 로컬·공유 상태 / 실제·예시 / 필요한 준비
초기화·다시 입장·뒤로 가기 / 입력 중 보호 / 터치·키보드·동작 줄이기
직접 실행해 확인할 결과 (숫자/보이는 요소/수신 화면 등)
```

## 구현·검증에서 놓치지 않을 것

- 단계 진행은 사용자의 클릭/조작을 기준으로 한다. 멋대로 전체 대본을 재생하지 않는다. 배경 클릭을 쓰면 입력창·버튼·링크·선택 중인 텍스트는 제외한다.
- 내부 탭/장면을 바깥 푸터 페이지 이동과 분리한다. 첫 장면·다시 보기·뒤로 갔을 때의 상태를 정한다.
- 모션은 근거 있는 최종값을 보여준다. 동작 줄이기에서도 뜻이 남고, 계속 움직여야 이해되는 내용은 피한다. 비교는 같은 영역·같은 배율로 한다.
- 사진/MP4는 설명의 증거와 시연 재료다. 실시간 조작을 보여줄 목적이면 가능한 작은 작동 도구를 만든다. 실제 API·여러 기기 연결이 없는 모형을 운영 중 기능으로 소개하지 않는다.
- 편집 가능한 글자·사진·영상은 안정적인 ID와 정본 계약을 유지한다. 기능 블록 내부의 입력·데이터는 편집용 텍스트 드래그에 가로채이지 않도록 보호한다. 기능 수정은 대상별 요청/소스 변경으로 이어지게 한다.
- 결과마다 실제 브라우저에서 ‘처음 → 조작 → 변화 → 초기화/재입장’을 검사한다. 공유 기능은 별도 브라우저 둘 이상과 늦은 입장/재접속/권한·정리를 포함한다. 스크린샷만으로 동작 검증을 대신하지 않는다.

이 문서와 자동 검사가 GPT의 미적 판단을 자동 보증하지는 않는다. 자료 근거·핵심 메시지·실제 조작을 대조하고, 캡처에서 과한 텍스트/버튼·작은 증거 화면·겹침을 직접 검토한다.


## 차별화는 운영 흐름과 검증에 둔다

애니메이션·설문·AI 생성·시뮬레이션 자체를 고유 기능이라고 소개하지 않는다. Canva는 코드 없이 인터랙티브 앱·학습 도구·시뮬레이션을 만들고, Mentimeter는 파일 기반 생성과 대화형 편집을 제공한다. 비교 기능은 변하므로 대외 비교를 할 때 공식 문서를 다시 확인한다.

이 스킬이 우선할 방향은 다음과 같다. 모두 버튼 하나로 완성됐다고 주장하지 말고, 해당 프로젝트에서 실제 구현·검증한 범위만 전달한다.

1. **교실의 역할과 상황을 구현**: 진행자와 참가자가 다른 화면을 보고, 선택·제출이 실제 공유 상태를 바꾸게 한다. 수업 규칙·교사 통제·재입장·접속 실패까지 함께 설계한다.
2. **자료의 근거에서 작동 규칙으로**: 원본 PPT/대본의 목표와 사례를 읽고 도구·상황·선택 결과로 바꾼다. 수치와 규칙을 지어내지 않고 가정과 교사 확인 사항을 분리한다.
3. **수정 의도에서 검증된 변경안으로**: 페이지/요소 ID·버전·자료·구현 의도를 요청에 묶고, 실제 조작·원래 기능 보존을 검사한 변경안을 확인·취소·확정하게 한다. 예쁜 화면 캡처만으로 완성이라고 하지 않는다.
4. **연수 후에도 쓰는 자기 도구**: 발표용 효과를 넘어 교사가 실제 수업에 쓸 수 있는 도구와 수정 가능한 소스를 남긴다. 운영 서버·계정·배포 경로와 비용은 선택할 수 있게 한다. 장면별 독립 앱 추출은 현재 기본 편집기 기능이라고 주장하지 않는다.

편집기의 `수정 예시`는 위 가능성을 발견하고 구체적인 요청으로 연결하는 입구다. 로컬 추천은 GPT의 자료 분석과 다르며, 동봉 체험을 실제 서버/AI 결과로 표시하지 않는다. [체험 계약](editor-examples.md)을 따른다.

공식 비교 근거(2026-10-25 확인): [Canva Code](https://www.canva.com/ai-code-generator/), [Canva Code 2.0](https://www.canva.com/newsroom/news/canva-code/), [Mentimeter AI Assistant](https://help.mentimeter.com/en/articles/16730234-create-and-edit-mentis-with-the-ai-assistant).

장면 추천의 기본 단위는 **현재 연수 페이지**다. 내 자료의 글·사진·수치·질문을 사용해 전달 방식을 바꾸는 시안을 먼저 보여준다. 수업 앱 개발로 자동 전환하지 않는다. 별도 앱 구현을 요청받은 경우에만 [가계·기업 서버 예시](economy-lab.md)를 공유 상태 검증 참고로 사용할 수 있다.
