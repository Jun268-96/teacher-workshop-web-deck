# 선택형 참여 런타임

## 구현과 경계

동봉 `server/live.mjs`는 Node 내장 모듈만 사용하는 **실제 서버 참조 구현**이다. HTTP API+1.5초 간격의 순차 폴링으로 여러 브라우저가 같은 상태를 공유한다. 응답은 서버 디스크의 `.workshop-data/runs.json`에 임시 파일+원자적 이름 변경으로 저장한다. 브라우저 localStorage만 공유하는 시연이 아니다.

구현 블록: 선택형 투표, 응답 빈도 기반 워드 클라우드, Q&A+중복 방지 공감+질문 상태, 선택에 따른 사례 분기 결과, 마무리 한 줄. 공통 동작: 코드 입장/직접 참가 URL, 회차별 구분, 현재 활동 전환, 응답 시작/마감, 결과 숨김/공개, 진행자의 응답 숨김, CSV/JSON, 종료/삭제, 새로고침/네트워크 재접속.

미구현: QR 이미지 생성, 실시간 척도/퀴즈·해설/카드 보드/우선순위/자료 블록, 참가자 기기 관리, 익명 스팸 방지·강한 운영자 계정·분산 서버, Cloudflare용 영속 저장 어댑터와 공개 배포. 일반 링크 자료와 정적 사례 탭은 기존 템플릿을 재사용한다. 참여 기능이 있다는 이유만으로 승인된 강의에 강제로 넣지 않는다.

## 로컬 실행

생성한 프로젝트에서:

```sh
npm run live
```

Node 22 이상이면 npm 패키지 추가 설치 없이 실행된다. 기본 주소 `http://127.0.0.1:8792/`, 진행자 `/live-host/`, 참가자 `/participate/`. 터미널의 서버 운영 키는 채팅/저장소에 올리지 않는다. 로컬 UI에서만 새 회차 생성에 사용한다. 회차마다 별도 진행자 키와 참여 코드가 생긴다. 진행자 키는 sessionStorage, 참가자 토큰은 회차별 localStorage에 보관한다. 서버에는 해시만 보관한다. 키는 URL/참가자 데이터에 넣지 않는다.

예제 페이지에서 활동 JSON을 수정해 회차를 만든다. 첫 구성은 기능 시험용 일반 문구이며 검증된 사회정서학습 연수나 실제 교사 사례가 아니다. 실제 연수에서는 승인된 활동 제목/선택지/분기 설명으로 바꾼다. 진행자 화면의 참가 URL을 다른 브라우저에서 연다. 회차 내 활동을 바꾸면 참가자도 따라간다.

`127.0.0.1` 주소는 다른 선생님의 태블릿에서 열리지 않는다. 로컬 테스트 통과를 학교 다중 기기 공개 운영 완료라고 소개하지 않는다. 별도 HTTPS 주소+서버 운영 환경이 필요하다. 인터넷 공개는 요청/계정/비용/보존 범위를 확인하고 진행한다.

## 권한과 보존

- 운영 키: 회차 생성만. 회차 진행자 토큰: 해당 회차 운영/전체 응답/다운로드/초기화. 참가자 토큰: 해당 회차 응답/공개 결과/자기 제출 여부/공감만.
- 서버는 시작·마감·선택지·중복 제출·공감 중복·진행자 권한을 확인한다. 참가자에게 다른 참가자의 토큰·ID·숨긴 응답을 주지 않는다. 결과 미공개일 때 집계 응답도 내려보내지 않는다.
- 투표/단어/분기/한 줄은 한 명당 한 번, 질문은 회차 활동당 다섯 개. 참가자 500명, 블록 30개 상한이 있다. 브라우저 저장소를 지우고 다시 입장하면 새 익명 참가자다. 1인 1계정을 증명하는 인증은 아니다.
- 종료: 새 입장/응답/공감을 닫고 기록은 유지. 초기화: 확인 모달 뒤 해당 회차와 응답·권한을 삭제. 다른 회차는 보존.
- 기본 보존 기간은 생성 후 14일. 만료 회차 접근 시 서버가 삭제한다. 주기적 정리 작업은 아직 없으므로 공개 운영에서는 정기 정리·백업·삭제 정책을 추가한다. 이름 등 개인 정보를 입력할 이유가 없게 구성한다.
- 파일 저장은 단일 Node 프로세스 기준이다. 여러 프로세스가 같은 JSON을 동시에 쓰지 않는다. 운영 배포에는 DB/Durable Object 어댑터, 인증·제한·백업·관측과 HTTPS를 추가한다. 현재 정적 Cloudflare 하네스로 이 서버를 배포하지 않는다.

## 재사용과 실제 발표 연결

발표자료는 참여 서버 없이도 열린다. 참여 활동이 승인된 경우 해당 페이지의 링크/iframe을 `/live-host/?code=<회차>`에 연결하거나 소스의 API를 이용한 페이지별 렌더러를 만든다. 참가자 화면과 서버가 활동 순서를 동기화한다. 기본 발표의 설정에서 회차를 연결하면 바깥 발표 이동의 공개 페이지 ID/제목도 서버로 전달한다. 화면 집중 on에서는 강의 중 TV 안내/현재 제목, 활동 중 현재 활동으로 이동하며 앱 안의 자유 탐색을 제한한다. 전체 슬라이드를 참가자에게 복제하는 미러링 기능은 아니다. 주석 요청/편집 저장과 참여 응답 저장도 별도다.

호스팅을 요청하면 Node 영속 디스크 호스팅과 Cloudflare DO 같은 어댑터 중 사용자 계정·운영 조건에 맞춰 선택한다. 새 가입·비용은 추정하지 않는다. 외부 서비스를 연결하지 않은 채 ‘실시간 공개 배포 완료’라고 말하지 않는다.

## 검증

스킬 루트에서 `node --test scripts/editor-live.test.mjs`로 서버/API/실제 브라우저 회귀 검사를 실행한다. Playwright는 기존 하네스의 설치 동의/경로 규칙을 따른다. 로컬 서버 테스트는 새 임시 폴더를 쓰고 종료 후 정리한다. 실제 연수 회차의 기록은 사용하지 않는다.

확인 대상: 진행자+격리 참가자2명, 늦은 입장, 새로고침, 네트워크 단절/복구, 디스크 복원, 중복 응답/공감, 결과 숨김, 응답 숨김, 질문 처리 상태, 종료·다운로드·회차별 초기화, 참가자의 진행자 조작 금지. 이 검사는 실제 태블릿/학교 네트워크/공개 HTTPS/외부 공급자 장애를 증명하지 않는다.

## 발표 설정과 화면 집중

기본 발표 화면의 독립된 설정 버튼과 편집기 상단의 설정 아이콘에서 같은 창을 연다. 로고/기관명은 필요 없다. `presentation-settings.js/.css`가 정적 Q&A 표시 설정과 실제 참여 연결을 맡는다. 기본 `presentationSettings.qaEnabled:true`이며 로컬 표시 선호는 덱별 localStorage 키 `workshop-presentation-settings:v1:<deckId>`로 저장한다.

참여 서버 연결 전 Q&A 버튼은 연결 안내를 열며, 화면 집중은 비활성화한다. 연결 화면에서 기존 회차 코드/진행자 키를 입력하거나 ‘회차 만들기’를 눌러 같은 출처의 진행 콘솔에서 생성한다. 내장 콘솔은 같은 탭의 sessionStorage에 권한을 보관하고 origin+정확한 iframe source를 검증한 준비 신호(코드만)로 연결한다. 키를 채팅·URL·발표 HTML에 넣지 않는다. 연결 회차/진행자 토큰은 sessionStorage에만 두고, 새로고침 때 서버의 최신 설정을 다시 읽는다. 연결 해제는 현재 화면의 연결만 끝내고 회차/설정/기록은 유지한다. 집중을 풀려면 off 또는 회차 종료를 사용한다.

공유 설정은 `POST /api/runs/:code/settings`의 `qaEnabled`, `focusEnabled`, `presentation:{slideId,title}`로 제어한다. 진행자만 쓸 수 있고, 형식/페이지 ID/제목 길이를 검사한다. 서버 디스크/회차 revision에 저장하므로 늦은 입장·새로고침·서버 재시작에도 같은 값을 받는다. 응답 snapshot의 role은 host/participant만 구분하며 토큰/해시는 보내지 않는다. 종료된 회차의 설정 변경은 거절한다.

- **Q&A on/off**: on이면 Q&A 블록의 질문 접수를 연다. 활성 활동이 다른 종류여도 질문 창으로 제출할 수 있다. off면 질문 진입점을 숨기고 새 질문/공감을 서버에서도 거절한다. 기존 질문·처리 상태·참가자의 미전송 질문은 삭제하지 않는다. 발표자는 질문 목록에서 답변함/나중에/새 질문을 관리한다. 참가자에게는 본인의 제출 내역만 별도 창에서 보여주며, 기존 공개 결과는 기존 reveal 권한을 따른다. Q&A 블록이 없는 회차는 설정을 비활성화한다.
- **화면 집중 on/off**: on이면 참여자 자유 활동 탐색을 막는다. 발표 페이지 이동 시 현재 제목과 TV 안내를 보여준다. 진행 콘솔에서 활동을 선택하면 발표 안내를 해제하고 현재 활동을 함께 연다. off면 자유 탐색으로 돌아가며 현재 활동이 아닌 응답 폼은 제출하지 못한다. 전환만으로 라디오 선택/작성 중 질문을 지우지 않는다. 종료는 집중을 자동 해제한다. 화면 잠금·외부 앱 통제·전체 슬라이드 미러링은 아니다.

설정 전송 중에는 추가 변경을 막고, 실패하면 이전 서버 상태로 되돌려 오류를 표시한다. 폴링은 중복 실행하지 않고 revision으로 오래된 응답을 거른다. 회차가 바뀐 뒤 돌아오는 요청은 적용하지 않는다. 파일로 내보낼 때는 Q&A 표시 선호만 공개 설정에 반영하고 연결 코드/진행자 권한/서버 질문/집중 잠금은 넣지 않는다. 오프라인 발표의 설정 버튼과 표시 토글은 유지되지만 실시간 기능은 서버 없이 작동하지 않는다. Node 참조 구현의 이 기능을 Cloudflare 어댑터 공개 배포 완료로 소개하지 않는다.
