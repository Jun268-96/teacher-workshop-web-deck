# 자료에서 장면을 추천하고 체험으로 고르기

새 연수/전체 재구성에서 자료를 읽은 뒤, 전체 페이지 구성안 전에 사용한다. 이미 사용자가 장면을 지정했거나 단순 수정 중이면 체험 선택을 반복시키지 않는다. 초보자에게 기능 목록을 작성해 오거나 긴 프롬프트를 쓰도록 요구하지 않는다.

## 맥락 복원

PPT/PDF·대본·기존 사이트의 실제 내용을 읽고 다음을 짧게 정리한다.

- **확인한 사실**: 청중, 목표, 필수 내용, 원본 순서, 사례·도표·그림의 위치, 명시된 활동/시간.
- **제안/추정**: 자료만으로 확정할 수 없는 대상·시간·실습 배분·기능. 사실처럼 적지 않는다.
- **필요한 확인**: 방향을 바꾸는 누락만 짧은 선택으로 묻는다. 실습 여부·필수 내용은 `intake.md`의 확인 원칙을 유지한다.

예: “자료의 A/B/C는 유지하겠습니다. 추가로 꼭 넣을 내용이 있나요? 없음/있음.” “사례 비교 뒤 짧은 실습을 제안합니다. 실습 포함/설명만/미정.” 사용자가 이미 명시한 답은 다시 묻지 않는다. 원본의 수치·인용·개인 경험을 검색이나 추정으로 만들어 채우지 않는다.

## 기능을 장면으로 번역

`assets/scene-lab/catalog.js`의 메타데이터를 읽는다. CSS 용어를 아는지 묻지 말고 **실제로 보게 될 변화**로 설명한다. 다음 기준으로 가장 어울리는 안 하나와 필요한 대안만 1~2개 제안한다. 열여섯 개를 모두 필수 선택지로 내밀지 않는다.

| 원본에서 찾은 신호 | 우선 살펴볼 기능 |
|---|---|
| 단계·정답을 차례로 설명 | `reveal`, `flip` |
| 짧은 핵심 문장·장 전환 | `kinetic` |
| 수치·규모·진행 과정 | `motion`, `scrub` |
| 여러 사진/스크린샷, 같은 자료의 변화 | `carousel`, `compare` |
| 복잡한 도표·작은 글자·위치별 설명 | `spotlight`, `hotspot` |
| 긴 시간 흐름, 전체에서 부분으로 이동 | `scroll`, `transition` |
| 교실 상황·대응 선택·우선순위 구성 | `branch`, `sort` |
| 참가자의 인식·의견·키워드 수집 | `poll`, `cloud` — 참여 방식 확인 후 제안 |
| 표지·핵심 오브젝트의 입체감 | `tilt` — 장식 자체를 학습 효과로 소개하지 않음 |

각 추천은 **원본 파일/쪽/문단 → 이 기능이 전달을 돕는 이유 → 발표자 조작 → 청중에게 보이는 변화 → 필요한 준비**를 연결한다. “멋있어서”만으로 고르지 않는다. 원본을 읽지 못했으면 가정한 일반 예시임을 밝힌다. 추천 수를 채우려고 억지로 기능을 붙이지 않는다.

## 직접 체험 보여주기

동봉 예시는 일반적인 기능 체험이다. 승인 전에도 **기존 체험 자산을 열거나 복사해 보여줄 수 있다.** 이것을 사용자 연수의 본격 제작, 새 개인 사례 제작, 설치나 공개 배포 허가로 해석하지 않는다.

Node가 있으면 외부 패키지·계정 없이:

```sh
node <skill-dir>/scripts/preview-scenes.mjs --dest <new-preview-folder> --serve --recommend reveal,compare,motion
```

출력된 URL을 사용자에게 열어 준다. 처음 열리는 장면은 `recommend`의 첫 ID이며 추천 기능에는 표시가 붙는다. 전체 기능도 탐색할 수 있다. 특정 장면 링크는 `#compare`처럼 ID를 붙인다. 기존 폴더는 덮어쓰지 않는다. Node가 없지만 파일 도구가 있으면 `assets/scene-lab/`을 별도 폴더로 복사하고, `assets/starter-deck/public/assets/fonts/`와 `assets/starter-deck/public/assets/favicon.svg`를 각각 체험 폴더의 `assets/fonts/`, `assets/favicon.svg`로 복사한다. 그 폴더의 `index.html`은 일반 브라우저에서 파일로도 열 수 있다. 미리보기에 Playwright·Cloudflare·AI API 설치는 필요 없다.

사용자가 설치를 거절했거나 화면을 볼 수 없다면 기능을 실행한 척하지 않는다. 원본과 연결한 짧은 전후 설명으로 선택을 도우며 이미 확정한 선택을 재질문하지 않는다.

## 선택과 반응 수집

체험 페이지의 ‘이 장면 담기’로 고른 뒤 ‘담은 장면’에서 복사/JSON 저장할 수 있다. `workshop-scene-selection/v1`에는 장면 ID와 다중 기기 집계 여부만 담는다. 자료를 올려 분석하거나 AI와 통신하는 기능은 아니다. 같은 작업의 브라우저 도구로 선택 내용을 읽을 수 있으면 사용자가 선택을 마쳤다고 한 뒤 화면의 선택 목록을 읽어 확인한다. 그 경로가 없을 때 복사/파일을 AI가 자료를 읽고 추천한 대화에 전달한다. 사용자가 대화에서 선호를 바로 말하면 파일을 요구하지 않는다. ‘효과 없이 간결하게’도 유효한 선택이다. 선택하지 않은 모든 기능을 싫어한다고 추정하지 않는다.

사용자의 명시적인 반응도 `workshop/scene-selections.md`에 짧게 기록한다: 선호/제외한 기능, 이유, 자료 위치, 운영 조건. “휴대폰 안 씀”, “이 효과는 유치함”, “사진 비교는 좋음” 같은 말은 다음 제안의 제약이다. 사용자에게 같은 내용을 기획서로 다시 작성하게 하지 않는다.

## 선택 후 전체 구성안 확인

선택한 기능과 원본 내용을 연결해 모든 페이지의 제목·메시지·화면 상태·발표자/참가자 행동·시간을 제안한다. 필수 내용/실습 확인과 총 시간도 함께 대조한다. **예시 선택은 전체 구성안 승인이나 제작/배포 허가가 아니다.** 선택 JSON의 `pagePlanApproved` 값이나 저장 파일만 보고 승인됐다고 판단하지 않는다. 실제 대화의 확인을 받아 `decision-guides.md#page-plan-approval`에 따라 기록한 뒤 제작한다. 이미 승인받은 안은 다시 확인하지 않는다.

## 구현 경계

- 시각 효과는 CSS, 버튼·슬라이더·숫자·선택 상태는 소량의 JavaScript로 동작한다. 모든 것을 “CSS만으로 실시간 처리”라고 소개하지 않는다.
- 설문/단어 예시는 **한 브라우저 체험**이다. 가짜 참가자 응답이나 집계를 섞지 않는다. 여러 기기의 기록을 실제로 모으기로 선택하면 `participation-runtime.md`의 서버/권한/다중 클라이언트 검증을 추가한다.
- 사진 슬라이드는 내장 **예시 도식**을 사용하고 사용자의 사진도 이 화면 안에서만 불러올 수 있다. 원본 수업 사진이나 실제 프로젝트 화면인 척하지 않는다. 다른 장면으로 이동하면 사진 URL을 해제한다.
- 모션은 사용자의 재생/클릭으로 시작하고, 초기화·키보드/터치 대안·동작 줄이기를 유지한다. 새로운 브라우저 API는 기능 탐지하고 기본 상태 전환으로 대체한다.
- 복잡한 효과는 `scene-effects-research.md`의 출처와 구현 경계를 확인한다. 중요한 설명과 조작을 애니메이션 지원 여부에 의존시키지 않는다.
