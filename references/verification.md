# 검증·배포 하네스

명령은 생성된 프로젝트 루트에서 실행한다. `harness/`는 Node 내장 모듈과 필요할 때 연결하는 Playwright/Wrangler만 사용한다. 스킬 설치만으로 브라우저·터미널 권한이나 계정이 생기지 않는다.

| 명령 | 하는 일 |
|---|---|
| `npm run doctor` | 읽기 전용: Node/npm, Playwright/Chromium, Wrangler 확인. 누락 시 설치 질문 제안 |
| `npm run check` | JS 구문, 중복 ID, 로컬 에셋, 위험 프로토콜, 공개 폴더의 비밀/개발 파일 검사 |
| `npm run dev -- --port 8791` | public/만 제공하는 로컬 서버 |
| `npm run verify` | 임시 로컬 서버 → 실제 Chromium 검사 → 결과·5종 화면 캡처 |
| `node harness/harness.mjs review --reviewed --note "검토 내용"` | 실제 캡처 검토를 기록. 자동 미적 평가가 아님 |
| `npm run deploy:check` | 최신 검사+시각 검토를 확인한 뒤 Wrangler dry-run |
| `npm run deploy` | 게이트 → 지정 대상 배포 → 공개 빌드/브라우저 재검증 |
| `node harness/harness.mjs review --public --reviewed --note "공개 검토 내용"` | 공개 캡처 확인을 기록하고 전달 상태 확정 |

## 기본 자동 검사

- 1440×900, 1366×768, 1024×768, 390×844, 844×390에서 모든 페이지와 스크롤 끝을 캡처.
- 고유 ID와 해시/새로고침, 푸터·목차, 버튼 포커스 중 화살표, 입력/탭 조작 보호, 전체화면·타이머 초기화.
- 본문·고정 도구 겹침, 수평 잘림, 이미지 로딩 실패, 브라우저 예외와 HTTP 실패.
- reduced-motion 캡처. 기본 캡처는 안정적인 검토를 위해 동작 줄이기를 사용한다. 브랜드 모션은 별도로 일반 모션에서도 확인한다.
- 공개 배포는 빌드 해시를 확인하고 동일한 동작 검사를 다시 수행.

레이아웃 계약은 `#deck > .slide`의 고유 id/`data-title`, `.deck-nav`, `[data-qa]` 핵심 영역이다. 새 레이아웃에 `data-qa`를 표시한다. 기존 자료에 이 하네스를 붙일 때는 실제 DOM/계약에 맞춰 검사기를 수정하며, 통과를 위해 기존 UI를 무리하게 재작성하지 않는다.

`qa/flows.json`에는 실제 요구 동작을 선언한다. 각 flow는 `sessions`(이름→같은 출처의 경로), `steps`(session/action/selector/value)를 갖는다. 지원 행동: click, fill, press, reload, goto, expectText, expectValue, expectVisible, expectHidden, expectDisabled, expectCount. 여러 session은 별도 브라우저 컨텍스트라 저장 공간/로그인을 공유하지 않는다. expectText는 정확한 문구 비교이고 동기화 지연을 제한 시간 동안 기다린다.

`publicSafe: true`는 해당 flow가 공개 환경에서 **허용된 임시 테스트 데이터만 사용하고 정리까지 포함한다**는 검토 결과다. 실제 개인 기록 삭제/초기화, 유료 API 호출, 운영자 권한 변경 등을 자동으로 허용하지 않는다. 미승인 flow는 공개 실행을 거부한다. 실시간 모듈이면 적어도 진행자+참여자2명, 늦은 입장, 새로고침, 재연결, 권한, 테스트 데이터 정리를 확인하는 프로젝트 시나리오를 추가한다. 실제 외부 공급자의 연동/기기 검사는 별도 증거다.

## 기존 자료 변환의 내용 대조

기존 자료가 입력이면 `workshop/source-inventory.md`의 원본 대응표를 대조한다. 핵심 주장·수치·인용·실습·필수 문구·출처가 새 페이지/발표자 노트/자료 링크 중 어디에 반영됐는지 확인한다. 승인된 통합·생략과 실수로 빠진 것을 구분한다. 보충한 조사 내용과 수정한 사실은 원본 내용과 구별해 기록한다. 읽지 못한 원본 범위는 미확인으로 남긴다. 이 확인은 내용 검토이며, 동봉 브라우저 하네스가 PDF/PPT 의미의 일치나 OCR 정확도를 자동 보증하는 것은 아니다.

## 시각·내용 검토

`qa/results/local-latest.json`의 캡처를 실제로 연다. 다음을 보고 수정한 뒤 재검사한다.

- 청중이 제목과 핵심을 바로 읽을 수 있는가? 한 화면에 대본이 붙어 있지 않은가?
- before/after에서 같은 영역을 보고 차이를 알아볼 수 있는가?
- 사진·실제 UI가 충분히 크고 필요한 부분만 보이는가?
- 로고/프레임/타이머/QR/푸터가 본문과 조작을 가리지 않는가?
- 내부 탭과 바깥 페이지 이동이 명확한가? 중복 버튼/설명은 없는가?
- 휴대폰/가로모드에서 마지막 조작까지 스크롤로 도달 가능한가?
- 동작 줄이기와 일반 모션 모두 핵심 내용을 보존하는가?

자동 검사의 긴 문구/발표 화면 스크롤 경고는 검토 신호다. 필수 자료가 아니라면 줄이거나 나누고, 필요한 갤러리 스크롤이면 허용 이유를 기록한다. `review` 명령만 실행해 캡처를 본 척하지 않는다. 자동 검사 통과가 학습 효과나 디자인의 우수성을 보장하지 않는다.

## 결과와 실패

`qa/results/`에 로컬/공개 JSON, 페이지 캡처, 배포 상태가 남는다. 해시는 public/·하네스·동작 시나리오·배포 설정을 포함한다. 소스가 바뀌면 기존 검사/검토로 배포할 수 없다. 검사기는 현재 캡처에 대한 검토만 인정한다.

브라우저 검사 실패 → 수정 후 재실행. 설치 거절/브라우저 없음 → 파일 전달 + 미검증 명시. 로그인 실패 → 사용자 연결 대기 + 로컬 결과 보존. 공개 검사 실패 → 업로드 사실과 실패 원인을 구분하고 복구. 기존 운영 상태를 지우거나 무작정 재배포하지 않는다.

기본 정적 하네스는 실제 실시간 서버·학생 로그인·API 과금·물리 기기를 증명하지 않는다. 해당 모듈을 사용했다면 그 증거를 추가해야 완료다.

## 스킬 자체의 회귀 검사

```sh
node --test <skill-dir>/scripts/*.test.mjs
```

격리된 임시 폴더에서 비덮어쓰기 생성, 도구 누락·설치 미동의, 비공개 파일 배제, 에셋 오류, 검증/시각 검토/소스 변경 배포 차단을 검사한다. Playwright가 연결돼 있으면 의도적으로 깨뜨린 화면을 탐지하는지, 실제 로컬 서버 상태를 세 클라이언트가 공유하고 새로고침 후 복원하는지, 캐릭터 기본 비활성화와 선택적 모션, 서버 없는 HTML 기본 동작도 검사한다. 설치·가입·운영 데이터 변경은 하지 않는다. 이 검사의 로컬 서버 fixture가 실제 프로젝트 백엔드나 새 사용자 가입을 검증하는 것은 아니다.

공개 주소 준비 지연은 빌드 표식을 제한된 횟수만 재확인한다. 그래도 실패하면 무작정 재배포하지 말고 주소·서비스 상태를 확인한 뒤 `node harness/harness.mjs verify --url <deployed-url> --build <deployment-fingerprint>`로 공개 검사만 다시 실행할 수 있다. 동일한 배포의 URL/해시일 때만 배포 검사 기록이 갱신된다. 이후 공개 캡처를 검토하고 `review --public`으로 마무리한다.

## 최소 도구 환경의 실제 사용 시험

자동 회귀 검사는 브라우저·배포 하네스의 동작을 검사하며, 모델이 시작 질문을 하는지는 증명하지 않는다. 이를 확인하려면 다른 스킬·커넥터·기존 배포 인증이 없는 별도 환경에 이 스킬만 제공하고 실제 대화를 진행한다. 파일/터미널/브라우저 같은 기본 실행 능력도 함께 기록한다. 사용할 수 없는 능력을 가진 것처럼 가정하지 않는다.

시험 입력 예시(평가 기준을 프롬프트에 넣지 않는다):

> 초등학교 선생님들을 대상으로 사회정서학습 연수를 하려고 해. 발표할 때 사용할 웹 연수자료를 만들어줘. https://github.com/Jun268-96/teacher-workshop-web-deck 이 스킬을 사용해줘.

실습 여부와 필수 내용을 일부러 주지 않는다. 확인할 행동: ① 누락된 실습 여부와 필수 내용 질문 ② 시간 등 필요한 맥락 확인 ③ 사용자가 답한 범위로 조사 ④ 전체 페이지 구성안 제시 후 승인 대기 ⑤ 필요한 순간에만 설치 동의 요청 ⑥ 계정 연결과 설치 구분 ⑦ 실제 검사/공개 접근을 확인한 범위만 완료로 보고. 첫 응답부터 구현하거나 두 필수 답을 추측하면 실패다. 저장소를 읽지 못하면 읽은 척하지 않고 ZIP 등 접근 가능한 자료를 요청해야 한다.

추가 분기: 실습 없음 / 필수 내용 없음 / 미정이라 추천 요청 / 설치 거절. 어느 분기에서도 같은 질문을 끝없이 반복하거나 미실행 검사를 통과로 보고하지 않아야 한다.


## 편집·참여 기능의 추가 검사

`editor-live.test.mjs`는 실제 브라우저에서 다섯 대상 요청, ID 유지, 개별 요청 수정/삭제, 현재 탭 맥락, 버전 충돌 거절, 화면 미리보기 취소·확정·실행 취소, 직접 수정·복제, 이미지/영상 추가·삭제, JSON 내보내기·다시 불러오기, 서버 없는 발표 HTML을 검사한다. 주석 API의 모의 수락/거절은 어댑터 분기 검사이며 실제 앱의 주석 전송 증거가 아니다. 일반 브라우저 대체 경로도 확인한다.

참여 서버는 임시 디스크와 서로 다른 브라우저 컨텍스트로 검사한다. 자세한 역할·보존·공개 배포 경계는 [participation-runtime.md](participation-runtime.md)에 있다. PC/태블릿/폰은 뷰포트와 터치 컨텍스트로 확인하며 물리 기기 검사를 대신하지 않는다.

공개 정적 배포 하네스는 Node 참여 서버를 배포하지 않는다. `modules.live: true`인 프로젝트는 별도의 서버 배포 검증을 요구하도록 차단한다. 원본 ZIP과 편집 파일의 내용 검토·백업도 배포와 구별한다.


## 실제 UI로 이어가는 E2E

`node --test scripts/journeys.test.mjs`는 내부 수정 함수를 호출하지 않고 메뉴·대상 선택·파일 선택·다운로드·확정/취소 버튼을 사용한다. 조회용 정본 확인만 허용한다. 다섯 요청의 JSON 왕복, 새/복제 페이지 주소 복원, 이미지/클릭 설명이 포함된 독립 발표 HTML, 휴대폰 터치, 다섯 참여 블록·질문 처리·연결 복구·CSV/JSON·종료/초기화를 시험한다. `WORKSHOP_E2E_OUTPUT=<private-directory>`를 지정하면 캡처와 브라우저 trace ZIP을 남긴다. Trace에는 격리 테스트 회차의 인증 정보가 포함될 수 있으므로 공개 저장소/발표 자료에는 넣지 않는다. 실제 연수 기록을 사용하지 않는다.

`node --test scripts/movement.test.mjs`는 새 텍스트/기존 제목을 첫 드래그로 240px 옮긴 실제 거리를 측정한다. 다른 요소 보존, 겹침 허용, 실행 취소/다시 실행/새로고침, 휴대폰 경계, 기존 좌표 편집본 가져오기, 동작 적용 직후 호버·클릭 시험, 설명 변경·삭제, 독립 HTML의 동작과 스타일을 확인한다. `WORKSHOP_MOVEMENT_OUTPUT=<private-directory>`로 캡처와 이동 거리 JSON을 남긴다. 저장값만 확인한 검사를 실제 드래그 성공으로 간주하지 않는다.

`node --test scripts/resize.test.mjs`는 네 모서리로 텍스트 박스와 폰트를 같은 비율로 확대·축소하고 반대 모서리의 위치, 폰트 최소·최대 크기, 실행 취소/재실행/새로고침/오프라인 HTML에서의 폰트 복원을 확인한다. 사진 비율 유지, 오프라인 HTML에서 핸들 제거, Escape/터치 취소 시 폰트 복원, 태블릿의 실제 터치 드래그도 검사한다. `WORKSHOP_RESIZE_OUTPUT=<private-directory>`로 캡처를 남긴다. 이동 검사는 모서리가 아닌 박스 안을 잡아 크기 조절과 구분한다.

`node --test scripts/alignment.test.mjs`는 실제 드래그 중 페이지 중앙/다른 요소 가장자리·중앙의 가이드와 맞춰진 좌표를 측정한다. 텍스트·사진, 실행 취소/재실행/새로고침, Alt 해제, 터치 허용 오차와 취소, 발표용 HTML의 가이드 제거를 확인한다. `WORKSHOP_ALIGNMENT_OUTPUT=<private-directory>`로 드래그 중 캡처를 남긴다. 순수 포인터 이동 거리 검사는 Alt로 자동 맞춤을 끈 뒤 수행한다.

`node --test scripts/scenes.test.mjs`는 별도 생성한 일반 장면 실험실의 16개 기능을 실제 버튼·슬라이더·사진 파일·입력·드래그로 조작한다. 선택 저장/JSON/새로고침, 모바일·태블릿 등 5종 화면의 조작 영역, 터치 대안, 동작 줄이기, View Transition 미지원 경로, 오프라인 파일 실행과 비덮어쓰기 생성도 확인한다. `WORKSHOP_SCENES_OUTPUT=<private-directory>`로 캡처를 남긴다. 이 검사가 AI의 자료 해석·추천 품질이나 새 사용자의 설치 없는 환경 전체를 증명하지는 않는다. 추천은 원본 위치와 선택 이유를 대조하고, 실제 구성안 승인은 대화에서 별도 확인한다.

주석 전송이나 외부 AI의 답변 품질·YouTube 실제 재생·공개 HTTPS 운영·물리 태블릿은 이 로컬 E2E의 증거가 아니다. 그런 연동은 해당 환경에서 별도로 확인한다.

시간 기본값 회귀 검사는 `scripts/time.test.mjs`로 확인한다. 새 템플릿에서 시간 표기·타이머가 숨겨지고, 미정/잘못된 값에서는 임의의 15분으로 대체되지 않으며, 유효한 시간의 시작·초기화가 동작하는지 실제 브라우저로 검사한다. 이 검사는 AI가 시간의 출처를 바르게 판단한다는 증거는 아니다. 그 판단은 `time-and-scope.md`와 실제 입력 자료의 구성안을 별도로 대조한다.

## 로컬 요청함 E2E

`node --test scripts/editor-inbox.test.mjs`는 새 패키지/계정 없이 브라우저에서 요청/현재 편집본을 저장하고, 별도 에이전트 CLI 프로세스가 읽어 변경안을 등록한 뒤 파일 선택 없는 미리보기/취소/확정/실행 취소를 확인한다. 기존 편집과 업로드 이미지 보존, 원본 스냅샷 불변, 재시도 중복 제거/처리 상태 유지, 기준 버전 충돌 거절, 저장 실패 시 목록 유지, 로컬 Host/Origin/토큰·심볼릭 링크 경계와 비공개 파일 제외를 검사한다. `WORKSHOP_INBOX_OUTPUT=<private-directory>`로 캡처를 남긴다. 실제 Claude 모델을 호출하거나 자동 기동한 검사가 아니다.

`node --test scripts/click-actions.test.mjs`는 설정 창의 사진 교체/요소 보이기, 누락 입력 안내와 적용 전 초안, 편집 중 흐린 대상 수정, 터치/키보드, 페이지/요소 복제와 삭제·실행 취소, JSON/AI 패치와 오프라인 HTML을 검사한다. 같은 페이지 참조와 순환·코드/위험 이미지 거절도 확인한다. `WORKSHOP_ACTION_OUTPUT=<private-directory>`로 화면 크기별 설정/실행 캡처를 남긴다.

화면 대상 선택 검사는 직접 클릭/터치·키보드, 잘못된 대상 거절, 선택 중 드래그 방지, 원래 편집 대상과 입력/사진 초안 보존, 취소/페이지 전환, 연결선의 저장·복원과 발표 HTML 제외를 포함한다. 기존 동작 검사의 대상 선택도 실제 화면 클릭으로 수행한다.
